# AIV Small Data Volume Ping-Pong and Large Data Volume Degradation Adaptation

| Feature | HCCL Implementation | Simulator Adaptation | Current Boundary |
| --- | --- | --- | --- |
| AIV Small Data Volume Ping-Pong | Enabled when `len * sizeof(T) <= 512 KiB`, alternating between `PONG + FLAG2` / `PING + FLAG1` based on tag parity, with the trailing `BarrierAll()` omitted. Currently used explicitly for **AllGather, equal-length AllToAll, ReduceScatter LocalTree/LocalTreeCoreCtrl**. | Models the full 65 MiB `aivCommInfo` according to the HCCL layout, including two data regions and flag regions; `Record/WaitFlag` follows the current `gmOutOffset`, and resets back to the `FLAG1` start address when cleared. | The simulator fixes tag to `1`, currently covering only the **PONG + FLAG2** branch. |
| AIV Large Data Volume Degradation | In normal `AIV` mode, when the selector data volume `>= 8 MiB * rankSize`, or data volume `> cclBufferSize * 16`, AIV returns `NOT_MATCH`; then it continues to select AICPU, and upon matching, sets the execution mode to `AICPU_TS`. | Supports updating the current operator expansion mode from `AIV` to `AICPU`, then launching or reusing the AICPU device process for execution, adapting to the real degradation flow. | This large data threshold currently applies to **AllReduce, AllGather, ReduceScatter, Broadcast, Reduce, Scatter, equal-length AllToAll**; **AllToAllV currently does not have this data volume degradation check**. `AIV_ONLY` skips the `8 MiB * rankSize` check, and when AIV does not match it will not degrade to AICPU; the `cclBufferSize * 16` limit still applies. |
